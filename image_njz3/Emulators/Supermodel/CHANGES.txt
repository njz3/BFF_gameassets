Commit 6f00a7d on 2026-10-26 by Benjamin

    Tile generator: the measured write rate for palette RAM only, one access for
    a tile RAM write

    8d4bbb5 halved the gap between writes (6.3 clocks) so that Scud Race's test 
    menu > GAME ASSIGNMENTS keeps its top lines. gm_matthew, who measured the 
    hardware, is clear that it is ~6.3 pixels (12.6 clocks): the snow of a whole 
    palette update in Daytona USA 2, dots 6-7 pixels apart. That is palette RAM: 
    two 8-bit SRAMs at 32 MHz, looked up twice per output pixel (two tilemap 
    layers), so a write only fits between lookups. Tile RAM, the 32-bit SGRAM at 
    the same clock, is read in bursts during active lines and not at all in the 
    blanking.

    Palette RAM writes keep 12.6 clocks (as upstream); a tile RAM write takes
    one 4-clock access, still in the one slot per tile pair during active lines. 
    Checked: GAME ASSIGNMENTS complete; scuddx's HUD at the rolling start right
    (broken without the timing); the linked attract car pushing the SEGA logo as 
    with upstream's timing. FFBRework.md section 2.15.

Commit c82e72e on 2026-10-26 by njz3

    Legacy3D: lighting, specular, alpha test and translucency as New3D, at no
    GPU cost

    Compared with New3D on Daytona USA 2, Scud Race, Le Mans 24, Sega Rally 2
    and Emergency Call Ambulance:

    - Lighting: the light intensity is clamped to 1 on Step 1.0 only (Step 1.5
     and later drive it beyond), the sun intensity to 0-1, Step 1.5's luminous
     polygons are 1.5 times brighter (fixed shaded: 1 + shade + ambient), and
     lit fixed shaded polygons use their fixed shade as the sun factor, all as
     New3D. Outdoor scenes were 15-20 % darker than New3D (Scud Race's sky about
     half as bright); their average brightness now matches it. The colour is
     clamped to 1 before the fog, as New3D.
    - Specular as New3D (Model 3): N.L to the power 8, 16, 32 or 64 with its
     multiplier for smooth shaded polygons, the reflection's Z for flat ones,
     times the sun intensity. The exponents 2 to 16 used before spread the
     highlight over whole cars (Scud Race's Gulf car silver instead of blue).
     Still per vertex.
    - Translucent polygons blend each pixel once (one stencil bit), as Real3D's
     stipple pattern does not pile up: it replaces the hack that did this for
     whole models of shadows only. The first one drawn at a pixel wins (New3D
     keeps the nearest one, which would need sorting or another pass).
    - Alpha test as New3D: texels below 32/255 alpha are discarded and the
     filtered alpha of the others is kept; texture alpha is used only where the
     polygon enables it; pixels below 1/32 alpha are discarded.

    Cost, measured on an Intel UHD Graphics at 1080p (GPU time of the 3D frame, 
    medians of 3 interleaved runs, e8674d3 with the depth buffer fix vs bbbc35b 
    plus this but the lighting, which adds a few operations per vertex and one
    per pixel): Daytona USA 2 2.94 -> 2.52 ms, Scud Race 2.69 -> 2.59, Sega
    Rally 2 3.63 -> 2.62, Le Mans 24 1.72 -> 2.62 (only its loading screen,
    where the game draws a hidden scene this engine now draws whole; New3D takes
    60 ms there), ECA 1.96 -> 2.13 (its sky is drawn). New3D takes 12 to 20 ms
    per frame on the same GPU.

    Known differences left: Sega Rally 2's dust trails, no mipmaps, and the line 
    of sight, which this engine does not emulate.

Commit bbbc35b on 2026-10-25 by njz3

    Legacy3D: depth and stencil buffers in SuperAA's frame buffer, decals and
    texture alpha as New3D

    SuperAA's frame buffer had a colour texture only. Legacy3D draws straight 
    into it, so whenever it is used (supersampling above 1x, CRT colours, an 
    AspectRatio presentation, the agent mode) Legacy3D had no depth and no 
    stencil buffer: the last polygon drawn won. The cars of Daytona USA 2 were 
    drawn inside out with their hood over their livery, its stands as bare 
    scaffolding. The frame buffer now has a 24-bit depth and 8-bit stencil 
    buffer when Legacy3D is the renderer (New3D draws into its own).

    With a depth buffer, compared again with New3D on Daytona USA 2, Scud Race, 
    Le Mans 24, Sega Rally 2 and Emergency Call Ambulance:

    - Pointer lists traversed forward, as New3D: Scud Race's sky panels and
     Sega Rally 2's cars are right this way (the backward order was chosen
     without a depth buffer).
    - Of two polygons at the same depth, the last one drawn wins (GL_LEQUAL),
     as New3D.
    - Layered polygons (decals) polygon by polygon instead of whole models
     only: in their own states, drawn after the others of their alpha state
     with the stencil and a depth bias in the vertex shader (1/512, as New3D).
     A uniform and a multiply-add per vertex, nothing per pixel.
    - Texture alpha only where the polygon enables it (header word 6 bits 0-2
     or contour processing), as New3D, whatever the texture format.
    - Texture offsets: X in bits 7-12 and Y in bits 0-4, as New3D.
    - An upload into any tile of a decoded texture invalidates it (only its
     first tile was checked).
    - A VROM model is dynamic if any polygon up to its last one reads the colour
     table (the walk stopped at a header whose word 6 is 0).

    Known differences left: Scud Race's Gulf car body (silvery instead of dark 
    blue), Sega Rally 2's dust trails, no mipmaps, and the line of sight, which 
    this engine does not emulate.

Commit d18b3fd on 2026-10-25 by njz3

    New3D: a frame with more ROM models than the cache holds no longer recaches
    them all every frame

    Daytona USA 2 Power Edition draws all its models, about 5000 at the eye and 
    3 million triangles, behind its 2D screen for about 4 seconds at boot (the
    "DRIVE BOARD INITIALIZING" screen). They overflowed the ROM model cache
    (MAX_ROM_VERTS) every frame: it was cleared and they were all cached again 
    the next frame, about 70 ms a frame, so the boot took some 13 seconds more.

    - DrawModel keeps the ROM polys within MAX_ROM_VERTS: a model that does not
     fit is taken back, the cache is full, and the models not cached yet are
     left out until it is cleared.
    - A full cache is cleared at most once a second (it was every frame here).
    - A frame that leaves out a ROM model draws none of them, as when the cache
     used to overflow.
    - A cached ROM model is looked up before walking its polygons for
     IsDynamicModel, and no empty entries are added to the map.

    Power Edition's boot: 3600 frames in 38 s instead of 48 (agent mode,
    1920x1080), no slow frames left. Frames of Daytona USA 2 and Scud Race
    identical to before; the other games' differences also occur between two
    runs of the previous build.

Commit 3e6c1c4 on 2026-10-24 by njz3

    Simulated net board: the link survives a game or Supermodel restart

    A cabinet that restarts (game reset, test mode, Supermodel quit and started 
    again) no longer leaves the ring with two masters or hung machines:

    - TCPReceive: a lost or out-of-step connection is taken out of the socket
    set
     and closed, and the next connection from the previous machine replaces it;
     packets are read whole (TCP can return fewer bytes) with their size
     checked; receives can wait with a timeout; an unusable port is logged.
    - TCPSend: a failed send disconnects, and Connect() works again after it.
    - SimNetBoard: the handshake goes in rounds (the master resends its GUID
     every 2 s, the slaves take the latest), a machine whose game resets the
     board tells the others the link is broken and links again, no data for
     10 s breaks the link, packets that are not a segment are dropped, and the
     segment size is kept when RAM reads 0. Logs: "Network board linked:
     machine N of M (master|slave), S bytes a machine" and why a link broke.

    Checked with hidden Supermodels in a ring on 127.0.0.1: Daytona USA 2 slave 
    restarted and relinked into a two-player race; four-cabinet races of Daytona 
    USA 2 and Sega Rally 2.

Commit 175add5 on 2026-10-14 by njz3

    Drive board: show each command of the main board to the Z80 for a whole
    frame

    With the drive board in its own thread, the Z80 ran its frame while the
    PowerPC wrote the next command: a command written during the Z80's frame
    could be seen for fewer NMIs than the program needs to take it (4 for Scud

    Agent mode: Supermodel driven by another program over stdin/stdout

    -agent lets a program, an autopilot or a test bench, drive Supermodel one
    command a line, as sm2-emu's --agent does. The window is hidden, the frames
    are rendered into SuperAA's frame buffer (forced at 1x) and read back, and

    carries the protocol, described in Agent.cpp and Docs/README.txt:
    - step [N] answers with the bytes written to the drive board meanwhile;
    - set/setraw/release/get hold an input or read what the game reads; inputs
    lists them;
    - obs (scaled RGB), shot (BMP), save/load, outputs, ram/mem, frame, quit;
    - ffb lists every force feedback command sent to an input, device or not,
    and servo
     journals what the drive board's Z80 writes to its outputs at each NMI, with
    an NMI count. Force feedback still goes to the mapped device, so what
    Supermodel sends can be checked against what a device such as vJoy receives:
    on Scud Race, every command reached vJoy in the same frame with the right
    value.

    AdjustConfig (no full screen, no vertical sync, background input),
    WindowFlags (hidden), WrapOutputs (records the drive board bytes), Run
    (instead of the main loop). SaveState takes an optional path as LoadState
    does, and both say whether they worked. The other hooks are small: SuperAA's
    forceTarget, a force feedback observer in CInput, the input types' range
    accessors, and the drive board's I/O observer and NMI counter.

Commit d5306e2 on 2026-10-13 by njz3

    Joystick drive board: translate Star Wars Trilogy's two servo boards as
    EPR-21119 drives them

    The board is the wheel boards' with two servo boards, one per axis, and its
    program computes the spring itself from the axes, sent to each servo board
    as a torque:

    - the stick is read where the program reads it, X on ADC channel 3 (port 26,
    servo 1)
     and Y on channel 4 (port 27, servo 2), instead of ports 24/25, which it
    only shows on
     its displays: the board's spring never saw the stick;
    - port 2E carries both registers, servo 1 in its low nibble and servo 2 in
    its high one,
     each the wheel boards' register less its F, with the value written just
    before it
     (2A, then 2D, then 2E): they were paired with the previous NMI's registers;
    - each servo is translated as on the wheel boards: FE a torque (servo 2
    wired the other
     way round), FC 0-3 a vibration on its own axis, FB the gain, FF the motor
    idle; sent
     once a frame;
    - no self-centre of Supermodel's own: 7F/81 is the board's spring at rest;
    - the board restarts on C9 (the game never sends CB); C8 skips the start-up.

    The servos are saved in a block of their own, JoystickBoardServos, so that
    older save states still load. Measured through vJoy over two games, the
    stick sweeping both axes: the constant force pushed it back towards the
    centre whenever it was off-centre, X 5476 times out of 5476, Y 4508 out of
    4508; before, as often away from it as towards it.

    NUM_FF_EFFECTS was 3 for the 4 effects of EForceFeedback (constant force,

Commit 10ebc3b on 2026-10-13 by njz3

    Drive board: show each command of the main board to the Z80 for a whole
    frame

    With the drive board in its own thread, the Z80 ran its frame while the
    PowerPC wrote the next command: a command written during the Z80's frame
    could be seen for fewer NMIs than the program needs to take it (4 for Scud
    Race's), and was lost. Scud Race often sends a new command at every frame (a
    hit: 20 17 9C 2F); a lost 2F left the torque gain at 4 %.

    The commands now go through a small queue, guarded by a mutex: each one is
    shown to the Z80 from the start of its next frame, for the whole frame. This
    applies to the wheel, joystick and billboard boards, which go through
    CDriveBoard::Write and RunFrame.

Commit edb11dc on 2024-06-13 by Ian Curtis

    Performance improvements The old texture code was being bottle necked by the
    texture reads. We mirrored the real3d texture memory directly, including the
    mipmaps in a single large texture. I *think* most h/w has some sort of
    texture cache for a 2x2 or 4x4 block of pixels for a texture. What we were
    doing was reading the base texture, then reading the mipmap data from a
    totally separate part of the same texture which I can only assume flushed
    this cache. What I did was to create mipmap chains for the texture sheet,
    then copy the mipmap data there. Doing this basically doubles performance.

Commit c039d08 on 2023-12-26 by Ian Curtis

    Add supersampling anti-aliasing Late christmas present. Due to the way alpha
    works on the model3 adding regular anti-aliasing doesn't really work.
    Supersampling is very much a brute force solution, render the scene at a
    higher resolution and mipmap it.

    It's enabled via command line with the -ss option, for example -ss=4 for 4x
    supersampling or by adding Supersampling = 4 in the config file.

    Note non power of two values work as well, so 3 gives a very good balance
    between speed and quality. 8 will make your GPU bleed, since it is
    essentially rendering 64 pixels for every visible pixel on the screen.

Commit 40c8259 on 2022-11-07 by Ian Curtis

    Rewrite the whole project for GL4+. I figured if we removed the limitation
    of a legacy rendering API we could improve things a bit. With GL4+ we can do
    unsigned integer math in the shaders. This allows us to upload a direct copy
    of the real3d texture sheet, and texture directly from this memory given the
    x/y pos and type. This massively simplifies the binding and invalidation
    code. Also the crazy corner cases will work because it essentially works the
    same way as the original hardware.

    The standard triangle render requires gl 4.1 core, so should work on mac.
    The quad renderer runs on 4.5 core. The legacy renderer should still work,
    and when enabled a regular opengl context will be created, which allows
    functions marked depreciated in the core profiles to still work. This will
    only work in windows/linux I think. Apple doesn't support this.

    A GL 4.1 GPU is now the min required spec. Sorry if you have an OLDER gpu.
    GL 4.1 is over 12 years old now.

    This is a big update so I apologise in advance if I accidently broke
    something :]

Commit e93c5d7 on 2021-11-28 by Matthew Daniels

    PowerPC IRQ line deassertion; DMA only fires interrupts when required

    PowerPC no longer clears its own IRQ line; it is now cleared by the IRQ
    controller when there are no more pending interrupts. Not all games clear
    DMA interrupts so it was necessary to tweak the 53C810 SCSI controller and
    the Real3D DMA interface to only fire interrupts if a certain register is
    correctly set. 53C810 has the documented DIEN (DMA Interrupt Enable)
    register; Real3D DMA seems to use the low bit of the dmaConfig register.

    Also I removed the net IRQ as no games seem to actually use it.

Commit 165926a on 2017-08-29 by Ian Curtis

    Modern hardware does backface culling in window space by calculating the
    face normal for the polygon, then doing a dot product against the view
    vector. The real3d pro-1000 on the other hand passes a pre-calculated face
    normal for each polygon which is used for culling. We were using this face
    normal to rewind the polygons so that regular backface culling would work.
    This worked 99.9% of the time. However this was failing on some models in
    Virtua Striker. The reason was because the pre-calculated face normals being
    passed were actually completely different to the actual face normals for the
    poly (not just inverted like you would expect). This broke our code. The
    solution was to emulate face culling directly in the vertex shader using the
    pre-calculated face normals directly. Only minimally tested this but
    hopefully there are no obvious regressions.
